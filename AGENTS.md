# Threads Mod project rules

## Patchlet-first changes

- Every release-bound APK feature, fix, or supported Threads version update MUST originate in a cataloged patchlet and an exact source-APK SHA-256 resolution. `decompiled/`, `work/`, `dist/`, and built APKs are evidence or output, never canonical source.
- Update the patchlet catalog, feature manifest and design note, canonical assets, exact resolution, semantic proofs, rewrite sets, AI updater task, idempotency ownership, release gates, and user documentation together. Do not publish a manually edited or dist-only APK.
- Every successful `Release` run MUST transactionally publish through a fresh, non-existing `PublishPath` below `dist/`, and every final release handoff MUST link that exact `dist/` artifact. A `SignedReview` candidate remains work-only, MUST NOT be copied or linked into `dist/`, and MUST NOT be described as a release.
- Every injected class descriptor, decoded rewrite path and anchor, manifest component, preference key, local database schema, and host hook MUST have exactly one owning patchlet. Reapplying the complete series to an already patched tree MUST be a content-identical no-op.
- Stable Java MUST NOT contain obfuscated Threads descriptors. Every private Threads seam belongs in a SHA-bound rendered Smali template or exact rewrite operation with bounded evidence. Session, callback, author-ID, Compose, and mutation semantics require human review before a resolution is marked verified.
- A new APK version MUST be replayed from the pristine exact input, fail closed on anchor or symbol drift, preserve native libraries, stay within the primary DEX method budget, pass archive/DEX/16 KiB alignment/signature/signer checks, and record source/output hashes plus static and runtime validation boundaries.
- Every release-tool or fixture invocation MUST pass only parameters declared by the called script. Patchlet 090 MUST prove this contract for the signed-APK gate path before a rebuilt or signed candidate can count as release-validated evidence.
- Every signed-evidence count or semantic expectation duplicated between a release wrapper and its positive fixture harness MUST be AST-proven identical and pinned to the reviewed literal. Patchlet 090 MUST fail closed on duplicate, nonliteral, missing, or divergent expectations.
- Broad final-DEX forbidden strings use case-insensitive substring semantics. Any pristine collision exception MUST be exact-source-SHA-bound to the full host identifier, remove only the colliding broad needle, and replace it with canonical-source plus signed targeted-class exact-case negative proof for every owning class; an unexplained exception or a global gate relaxation is forbidden.

## Account-action and network safety

- The clone application ID is `app.tree55.threads`. Renaming it is a patchlet-010 identity change that MUST move the manifest package, every provider authority, the dynamic-receiver permission, task affinities, account type and self-package references together, MUST NOT rename the mod's own Java packages or injected class descriptors, and MUST NOT rewrite a historical resolution. A rename produces a side-by-side install: it cannot upgrade a differently-named clone and the in-app updater MUST NOT attempt to bridge them.
- Mod activities MUST be non-exported and have no intent filter. The sole inline control MUST open the combined confirmation modal; no one-click bypass may skip its report fields. Reject missing/non-numeric targets and the active viewer, bind controls to an immutable row identity, and show Block success only after the native success callback.
- Every automatic, retry, and inline block MUST pass through the shared single-flight scheduler, viewer-scoped persistence, failure backoff, and `ThreadsBlockBridge`. Passive work alone is paced by the configured passive delay; manual inline work is not rate- or pace-capped. No feature may call the private Threads mutation helper directly.
- Each private seam in the direct-ID bridge (session cast, cache lookup, cache factory, cache placeholder creation, and guarded dispatch) MUST have its own narrow failure region and fixed diagnostic literal outside that region. A shared mutable stage register or broad catch around mod callbacks is forbidden; signed-DEX release evidence must prove the exact raw private calls, ID guard, handler topology, and literal-to-callback flows.
- A SHA-bound bridge resolution MUST use the reviewed session user cache for numeric-ID model construction when an exact cached model is absent; it MUST NOT add a profile-info network lookup prerequisite. Retired lookup callbacks and their terminal strings are forbidden in final DEX, and the constructed model ID MUST still equal the immutable target before mutation.
- Persist every attempt before calling `ThreadsBlockBridge`. A passive attempt MUST atomically persist its selected next-admission deadline before dispatch; that deadline MUST NOT be cleared or shortened after reservation. User-confirmed inline work MUST preempt automatic list work before another automatic attempt is selected. Never evict or reset queued/running manual work; process-interrupted work becomes explicit abandoned/review state rather than an automatic retry.
- Every terminal Block failure MUST produce a closed, versioned, bounded local diagnostic with a stable code plus stage, source, route, native-mutation state, retry-state persistence, bridge revision, and mirror applicability. Unknown input, viewer/target IDs, host objects, URLs, headers, tokens, response bodies, raw exception messages, and stack traces MUST NOT be copied into diagnostic text.
- If Threads confirms native Block success but the normal local completion save fails, install a bounded viewer/target completion-review quarantine before releasing scheduler ownership. That target MUST NOT enter backoff, an automatic queue, or another automatic mutation. Corrupt, oversized, or uncommitted quarantine state pauses automatic work fail-closed; only an explicit retry may atomically change a retryable manual queue item and remove its matching quarantine.
- Every backoff or passive-delay wait MUST schedule a wake-up. Activity replacement and account change MUST release the old owner into a fresh current-context drain. Forced-refresh intent MUST be bounded and viewer-scoped so old-account work cannot overwrite, transfer, or clear another viewer's request.
- Every Block-scheduler-critical `Handler.post` / `postDelayed` MUST check Android's boolean acceptance result. Rejection MUST release passive ownership or leave durable Block work in a bounded fail-closed pause. A Block watchdog that expires or is rejected after bridge dispatch MUST install viewer/target review quarantine before release, MUST NOT create automatic backoff/retry, and MUST leave inline work abandoned until an explicit atomic Retry removes its matching quarantine. Only the Block scheduler's best-effort toast delivery may ignore enqueue acceptance.
- Clone Blocker list reads MUST use only the reviewed HTTPS mirror allowlist of three fixed v3 bases, consulted in this exact declared order: GitHub raw first, jsDelivr second, then the AWS blocklist relay. The signed root is the exact URL `<base>manifest.json`; objects are `<base>objects/<name>` where `name` MUST be exactly 64 lowercase hex characters followed by `.json` or `.ndjson.gz` and MUST be validated before any URL text is formed. Every refresh MUST consult and independently verify the root from every allowlisted mirror and install only the strictly newest verified signed root; an equal timestamp keeps the earlier mirror, and no mirror may be skipped because an earlier mirror answered, returned 304, or served a root. Objects are provenance-free: they MAY be fetched from any allowlisted mirror in declared order (the winning root's mirror first) and MUST be rejected unless the SHA-256 of the received bytes equals the name the signed root transitively gave, checked BEFORE parsing. The retired whole-file `blocklist.json` URLs MUST NOT be compiled or fetched. `tree55.com` is forbidden in code and final DEX. Patchlet `070-consented-reporting` is the sole authorized Clone Blocker write path and owns exactly two reviewed POST destinations on that one host: `https://h0w1lwun39.execute-api.ap-southeast-1.amazonaws.com/v1/reports` for a consented report, and `https://h0w1lwun39.execute-api.ap-southeast-1.amazonaws.com/v1/installs` for one activation-statistics ping per installed build. No other write endpoint, host, or fallback is allowed unless a later explicit policy revision names and reviews it. Third-party analytics, advertising, attribution and crash-reporting SDKs are forbidden outright.
- The activation-statistics ping MUST send only the closed 13-key field set: the constant payload schema version `v`, install ID, clone package name, version name, version code, mod build, Android SDK level, manufacturer, model, primary ABI, language tag, time zone and send timestamp. Its install ID MUST be an HMAC of a local random secret over a fixed domain tag with no account, advertising, or hardware identifier as input, so it is neither the reporting pseudonym nor linkable to a Threads account. It MUST be sent at most once per installed build, MUST be disclosed in the mod Settings screen (the `CloneBlockerSettingsActivity` Reports card, which names every field it carries) before a later build can send another, and its failure MUST never affect Block, report, list, proxy or updater work. Threads account, target, username, permalink, post text, and free-text values MUST NOT appear in it.
- The sole inline control MUST open one `Block and report` modal. That modal owns the report reason, bounded post excerpt, persisted `Also block this profile` checkbox, one positive action, and Cancel. The positive action always durably queues the report; when the checkbox is checked it also schedules the immutable target through the shared Block scheduler, and when unchecked its label is `Report`. There MUST be no dedicated Report button, separate editor, exact-payload preview, consent checkbox, review step, or one-click bypass. A report MUST include a non-empty profile username, a canonical 4–24 digit profile ID, and a non-empty Unicode-safe post excerpt capped at 280 UTF-16 units. Reporting may occur only from that explicit positive-action tap; background delivery is not authority to create another report.
- The combined modal MUST give a concise disclosure that the action queues a report and that delivery can expose the stable per-install/account pseudonym, language/time zone, server-visible IP and User-Agent, and possible coarse location to the server operator; full access/retention and local outbox/history detail may remain in Settings. A report MUST be durably queued before network delivery, retry only while foregrounded, fail closed into review state on corrupt storage, and truthfully explain that cancellation can fail once delivery is active and cannot recall a server-accepted report.
- The only configurable Block limits are passive minimum delay 2–60 seconds and passive maximum delay 3–60 seconds, both in exact whole-second steps, atomically committed as one snapshot with defaults 4–10 seconds. Partial, mistyped, invalid, corrupt, or uncertain stored values pause passive work fail-closed. Manual inline work ignores this passive delay pair. Retired manual-delay, automatic/hour, target-budget, total/hour, total/day, and attempts/run keys are deletion-only and MUST NOT regain admission authority or UI controls.

## Passive blocking safety

- Patchlet `020-autoblock-runtime` is the sole owner of the verified-list database, refresh metadata, passive visible-match admission, durable passive-running state, and scheduler integration. Patchlet `060-inline-block-controls` owns exactly one visibility observation at its exact-SHA post/reply action-row seam; no other patchlet may add a second observer, enumerate the database into work, or restore whole-list batch selection.
- Passive refresh is always enabled and requires a valid live viewer while the clone is foregrounded. There is no opt-in switch and no in-app way to disable it; the mod Settings screen's Passive blocking card (`Always on. Refreshes the signed index every 10 minutes in the foreground, then blocks only listed profiles whose post or reply action row becomes visible.`) discloses the behaviour instead of gating it, and the clone MUST open with no mod dialog. Its ordinary cadence is exactly 600,000 ms measured between eligible foreground refresh wakes that follow a successful attempt. Before any attempted refresh starts, including a forced attempt, the runtime MUST install a process-local not-before guard and synchronously persist `list_refresh_not_before` as an exact Android `Long` equal to the checked current time plus 600,000 ms; overflow, wrong stored type, implausible future value, read failure, or commit failure pauses ordinary refresh fail-closed. When the attempt completes, the same worker MUST re-install both guards from completion time: exactly 600,000 ms after a successful attempt (installed, unchanged, or metadata-only result), or the next step of the fixed failure ladder 15,000, 30,000, 60,000, 120,000, 300,000 ms after a failed attempt, at most five ladder steps per foreground session and 600,000 ms thereafter. The ladder index is process-local, advances only on a completed failed attempt, resets on a successful attempt and on each background-to-foreground transition, and that completion-time re-advance is the only path that may replace a persisted guard with a shorter one; a ladder deadline is never longer than 600,000 ms. Reads MUST use raw-type validation and enforce the later of the durable and process-local guards, so pause, resume, Activity replacement, and process recreation cannot retry earlier than the persisted deadline. Background time does not promise exact Android scheduling; overdue work catches up on the next valid foreground resume. A forced list refresh starts directly when idle or remains one bounded viewer-scoped intent behind the active lane. Exactly two admission-time deadline bypasses exist: that forced refresh, and, once per foreground session and no sooner than 15,000 ms after the last admitted start, the first ordinary request while no valid verified generation is installed (`BlocklistStore.snapshot(context).valid` is false). Both MUST still install the new 600,000 ms deadline before work starts and MUST NOT clear, shorten, transfer, or reinterpret another viewer's durable deadline. Each root response is bounded to 4,194,304 bytes on both the declared Content-Length and the streamed byte count and to 524,288 characters after decoding; each group table to 65,536 bytes; each chunk to the lesser of its signed byte count and 262,144 gzip bytes, to 4,194,304 inflated bytes and to 8,192 rows; a root whose chunk caps exceed those compiled maxima, whose bucket bits exceed 16 or group bits exceed 8, or whose threads total exceeds 2,000,000 rows is rejected. Within one attempt a mirror MAY be retried immediately exactly once per root and once per object after a transport failure (the `IOException` family: timeout, DNS/connect, TLS, or a stream broken mid-body) and MUST NOT be retried after an HTTP status, oversized, cookie-refused, signature (including an object whose bytes do not hash to its signed name), schema, clock, stale, rollback, or target-cap result; an object failure moves to the next allowlisted mirror, and the install fails closed only when every mirror failed. A retained-failure `List fetch:` status MUST name each mirror's outcome in declared order from the closed token set `too_large`, `http_<status>` (or `http_other`), `timeout`, `unreachable`, `tls`, `io`, `signature`, `schema`, `clock`, `stale`, `rollback`, `target_cap`, `cookie_refused`, `internal`, chosen by exception type or typed field only (an object-phase failure is attributed to the mirror that served or refused the object, and `target_cap` covers row and bucket caps), and MUST NOT include a URL, host, header, ETag, body, exception text, or stack trace.
- The single freshest verified signed root chosen across the reviewed GitHub raw, jsDelivr, and AWS mirrors MUST atomically replace one indexed local generation: only chunks whose signed name differs from the committed generation (or every chunk when the bucket bits change or no valid generation exists) are downloaded, each is hash-verified and then stream-parsed row by row into a content-addressed staging table with bounded memory, and one transaction replaces the affected hash buckets, records every chunk and group name, and advances the generation. A 304 is accepted only from the exact mirror that produced the retained generation while that generation is usable, may advance only fetch metadata, and MUST NOT suppress a strictly newer verified payload from another mirror. A verified candidate whose signed timestamp is not strictly newer than the committed generation likewise advances fetch metadata only; it MUST NOT replace the generation, change its record counts, or clear the passive store-pause latch. Fetch, signature, object-hash, parse, schema, transaction, clock, timestamp, or invariant failure MUST preserve the previous verified generation and fail closed; staged chunks are never authoritative until the transaction commits. The signed timestamp text MUST parse to the exact supplied epoch-millisecond value before replacement, and every metadata read MUST reparse the stored text and require equality with the stored millisecond field. The whole chunk MUST be rejected, and the install with it, for a line that is not a JSON object, a malformed `i`, a threads id row with a missing or malformed `u`, a duplicate id, a row outside the chunk's bucket, or a row or byte count that differs from the signed group entry; a handle-only row (`u` without `i`) is a canonical non-target row that is bucket-checked and counted but not indexed. Only the threads partition is fetched. The retired SharedPreferences list blob is deletion-only and MUST NOT regain lookup or queue authority.
- Fetching and indexing MUST NOT create Block work. Passive admission may occur only after the exact post/reply UFI row reports a lifecycle-bound, clipped-viewport visible transition. Current coverage includes posts and replies, including those action rows rendered in profile post lists; it does not cover profile headers, search results, follower/following lists, or any surface without the reviewed action-row seam.
- The Compose visibility callback MUST perform no database, network, scheduler, or bridge work. It may call only a bounded memory-only registration API. Every geometry callback MUST idempotently re-establish its immutable token before forwarding visibility, so a same-process account reset cannot strand a remembered row. Registration, visible=true updates, manual enqueue, scheduler-owner acquisition, and `BlockRun.begin` are authority-granting entries and MUST execute on the main looper. An off-main path may only revoke or remove existing visibility/work authority; it MUST NOT register, make visible, enqueue, schedule lookup/drain, admit, reserve, or dispatch, and its revocation MUST be serialized under `PASSIVE_ADMISSION_LOCK` with the visibility-state lock so final admission cannot race it. One background worker owns indexed lookup, bounded deduplication, and removal on invisible/forgotten/abandoned lifecycle events.
- Indexed lookup MUST preserve three outcomes: valid match, valid non-match, and invalid/unavailable/corrupt store. Every invalid result MUST carry the generation actually observed by that lookup. An unknown-generation fault or a fault for the current committed generation MUST latch passive work paused, clear pending lookup/match authority, and MUST NOT be treated as a non-match; only a known observed generation strictly older than the latest committed verified generation may be discarded as stale. Only successful atomic installation of a strictly newer verified generation may clear that latch; a 304, retained generation, resume, ordinary non-match, or equal/older replacement cannot. Latch/clear and generation replacement MUST be ordered under `PASSIVE_ADMISSION_LOCK`.
- Numeric 4-24 digit Threads ID is the sole passive mutation identity. A normalized username index may assist lookup only; the signed chunks and stored database MUST reject duplicate normalized usernames (the stored normalized username carries a UNIQUE index, so a cross-chunk duplicate fails the install closed at commit), every exact-ID membership result MUST prove its normalized username is unique, and every visible registration for that ID MUST agree with the stored normalized username. Any duplicate or stored-visible conflict fails closed and username MUST NOT become mutation authority. Self, valid non-match, local-complete, already-blocked, queued/running, quarantined, invisible, stale-generation, and stale-viewer candidates MUST be skipped before reservation. The viewer-scoped completed-ID set MUST be raw-type checked, ID-validated, and bounded; corrupt or oversized state pauses automatic work rather than granting new authority.
- The exact-SHA bridge's callback-free passive preflight MUST finish before passive-running persistence or passive delay/attempt reservation. A native already-blocked result MUST durably mark local completion or install completion-review quarantine, release the owner without mutation, and reserve no passive delay or attempt. A fixed preflight failure likewise reserves nothing. After preflight, and again immediately before passive-running persistence, passive delay/attempt reservation, and `ThreadsBlockBridge` dispatch, the scheduler MUST establish complete current authority: main-thread owner, exact Activity/session/viewer and foreground generation, manual priority, valid passive delay/pacing state, completed/duplicate/quarantine state, visible immutable row, unpaused valid store, exact database generation, numeric-ID membership, and stored-visible username agreement. Each check and the following guarded action MUST share `PASSIVE_ADMISSION_LOCK` with atomic generation replacement; an earlier successful check is never continuing authority for a later action.
- Passive delay/attempt reservation is conservative. Once its atomic persistence succeeds, no later authority loss, manual preemption, scheduler handoff failure, bridge throw, or uncertain mutation may roll back, clear, or shorten the selected viewer-scoped passive deadline. Pre-reservation exits create no pacing deadline.
- A visible database match enters only the durable passive queue/state. User-confirmed manual work always preempts passive work before another passive target is selected. Each owner may retain only one immutable target string; it MUST NOT retain or iterate a visible-target collection, and any continuation MUST release into a fresh manual-first drain.
- Every passive attempt uses the same viewer-scoped persistence, failure backoff, watchdog, completion-review quarantine, and `ThreadsBlockBridge` as manual work, plus only the passive delay pair. Process-interrupted or mutation-uncertain passive work becomes abandoned/review quarantine without automatic retry. Passive visibility MUST NOT create, queue, or deliver a report.
- The indexed database metadata MUST expose the committed generation's total record count (installed threads id rows), its bucket bits, and the exact incoming-ID set-difference count summed over the buckets that install replaced (an id's hash range is fixed, so the per-bucket difference measured before that bucket's rows are removed equals the global difference). A reviewed v1-to-v2 migration uses `-1` only for a retained pre-feature generation; the reviewed v2-to-v3 migration preserves the generation, both timestamps and both counts, recomputes each retained row's hash into fresh tables and leaves the renamed v2 tables empty; a first verified install counts every row as new, and a verified 304 or a root that is not strictly newer records zero new rows. Activity and Settings Current status MUST show the live fetch/verify/index phase or retained failure (a retained failure naming each mirror's closed failure class on the same `List fetch:` line, never a URL, header, body, or exception text), total records, new records or Unavailable, and the current DB index state/generation; bounded polling must stop on pause/destruction and visibly fail closed if enqueue is rejected.
- Patchlet 090 MUST fail closed unless canonical, exact-host, generated-Smali, signed-DEX, and positive/negative fixture evidence proves exception-safe raw-type reads of the typed persistent refresh deadline, the 600,000 ms success cadence with the fixed 15/30/60/120/300 s five-step per-session failure ladder installed only at completion time, the non-clearing forced and missing-index admission bypasses, the 4,194,304-byte root bound on Content-Length and streamed bytes plus the signed per-object byte and row bounds, exactly one transport-only in-attempt retry per mirror per object, and closed per-mirror failure-class status with no exception text, URL, header, or body; validation of every object name against the 64-hex-plus-suffix grammar before URL formation; SHA-256 verification of every group table and chunk against the signed root before any parse; download of only chunks whose name differs from the committed generation; streamed row-by-row chunk parsing with bounded memory; timestamp text/millisecond rebinding; whole-chunk rejection of non-object lines, malformed ids, missing or malformed threads usernames, duplicate ids, out-of-bucket rows and count mismatches while handle-only rows are counted and not indexed; duplicate (UNIQUE-indexed) and stored-visible normalized-username rejection; tri-state invalid-store results carrying their observed generation, unknown/current-generation fault latching, strictly-newer-generation clear, and suppression only of known older stale invalid results; main-thread authority grants with lock-serialized off-main revocation only; one memory-only post/reply observer; complete authority immediately before passive-running persistence, passive delay/attempt reservation, and dispatch; conservative non-clearing passive deadlines after reservation; exact status metadata, per-bucket replacement and v1-to-v2-to-v3 migration semantics; and no fetch-to-mutation, database-enumeration, visible-set batch, same-owner continuation, retired capacity admission, or profile-header coverage claim. Static proof is not live scrolling, account mutation, or device-runtime proof.

## In-app update safety

- Patchlet `085-in-app-update` is the sole owner of update metadata endpoints, signature and schema verification, monotonic update state, update dialogs, artifact download, archive verification, and installer launch. Metadata reads MUST use only the exact HTTPS order GitHub raw -> jsDelivr -> AWS. `tree55.com`, redirects between provider classes, unsigned metadata, and alternate metadata or artifact fallbacks are forbidden.
- Update metadata MUST be a strict Ed25519-signed envelope with purpose `threadsmod-app-update`. Its exact wire fields are `v`, `purpose`, `packageName`, `revision`, `publishedAt`, `modBuild`, `minimumModBuild`, `versionCode`, `versionName`, `notes`, `apkSize`, `apkSha256`, `signerSha256`, and `downloadUrls`. The client MUST parse `publishedAt` once and internally bind/reuse that exact epoch result, then require the text to round-trip exactly as UTC `uuuu-MM-dd'T'HH:mm:ss.SSS'Z'`. It MUST also bind a positive monotonic policy revision, positive binary `modBuild`, `minimumModBuild` in 0..modBuild, clone application ID, target version, required policy derived from the minimum build, bounded notes and APK size, lowercase SHA-256, exact signer SHA-256, and reviewed independent artifact providers. Unknown, duplicate, missing, mistyped, lower/equivocating revision or build, implausibly future, noncanonical, alternate-ISO, or trailing data fails closed without changing accepted state. A valid old `publishedAt` is not rejected solely for age.
- The exact current resolution owns `CURRENT_MOD_BUILD=1` and target version `511407878` / `444.0.0.45.85-threadsmod.1`. The 415 resolution is historical and MUST NOT supply current release authority. Previously published builds without patchlet 085 cannot discover this bootstrap build and require one manual installation; only mod build 1 and later can receive subsequent prompts. An update is available only when signed `modBuild` is greater than the current build and signed artifact versionCode is greater than the installed clone. Persisted revision/build floors MUST be exact positive raw `Long` values whenever any policy key exists. Missing, partial, wrong-type, zero, corrupt, or uncommitted state MUST NOT grant a fresh baseline; a parsed envelope must exactly bind the typed revision/modBuild floors, and any mismatch may be repaired only by a signed candidate whose revision is strictly greater than the strongest parsed/typed revision. Policy persistence uncertainty MUST latch before commit, reject ordinary reads after a thrown/false commit, retain the strongest attempted verified policy as a process-local anti-rollback floor, and clear only after a successful live signed recommit. During that uncertainty, only the last successfully loaded or committed manifest may remain inside `UpdateStore`, and only when it requires the running mod build. Store may expose that fact only as a boolean; the controller may use it only for a noncancelable **Update unavailable** / **Retry** UI gate. It MUST NOT return or pass the retained manifest, show an Update action, open unknown-sources settings, download, verify, or launch an installer from retained state. Retained state MUST NOT supply anti-rollback, write, current-binary, download, or installer authority; a failed first-run commit or previously optional policy MUST NOT manufacture a lock. A required eligible update from a successful persisted load is noncancelable and Update-only; an optional eligible update offers Update and Later. Later may suppress only that exact verified revision and MUST NOT suppress a later or required update; optional back cancellation runs the normal fallback without persisting Later.
- A downloaded APK MUST remain private cache data, bounded to one fixed `threadsmod-update.apk` committed file plus one `threadsmod-update.apk.part` partial file, until its actual byte count and SHA-256 equal metadata, archive package equals the clone ID, archive versionName/versionCode exactly equal the signed target, archive versionCode remains newer than installed, and exactly one current signer, archive signer, and metadata signer all equal the resolution-pinned certificate. Failure MUST NOT open an installer. Installer launch may use only the existing non-exported clone FileProvider for `cache/shared/updates`, APK MIME type, read grant, Android's visible unknown-sources flow when required, and a user-visible package installer; silent/root install, exported updater components, and direct file URIs are forbidden.
- Checks are initiated on foreground and update UI/installer launch are bound to the current foreground Activity and still-current showing dialog. `UpdateController.onResume` MUST run first on every foreground resume, the no-applicable-update continuation `ModBootstrap` passes to it MUST be an empty non-capturing Runnable that shows no UI, and no mod dialog may precede, replace, or obscure a previously verified required update. A started metadata read or explicitly tapped download may finish and cache after pause, but MUST NOT show UI or launch an installer until a current foreground resume or tap. Worker-start failure MUST clear in-flight ownership, re-evaluate only the retained last-successfully-loaded/committed required policy described above, and otherwise run the fallback. Network unreachability MUST retain and enforce that policy for UI only but MUST NOT manufacture a required gate or lock a first-run app with no verified policy. Network streams, redirects, responses, files, and lifecycle ownership are bounded and fail closed.
