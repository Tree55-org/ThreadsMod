This patchlet adds a foreground-initiated update checker without adding another private Threads hook. An already-started metadata read or explicitly tapped APK download may finish into app-private cache after pause, but no dialog or installer may launch without the current resumed Activity. The 020-owned stable `ModBootstrap` delegates update arbitration to `UpdateController`; through revision 1 its fallback showed the then-existing demo dialog only after no applicable update prompt remained, and since revision 2 that fallback is the empty Runnable described above.

Update metadata is read every ten eligible foreground minutes from all three exact endpoints, in GitHub raw, jsDelivr, then AWS order. The complete three-mirror operation has a 24-second monotonic deadline; each attempt is capped by the smaller remaining whole-operation time or eight seconds, with at-most 3-second connect and 5-second read waits. A daemon deadline watchdog disconnects each live HTTPS connection so response headers or trickled body bytes cannot evade the deadline. All three are attempted so a lower-revision mirror cannot hide a newer valid revision. The highest valid signed revision wins; divergent signed payloads at that highest revision fail closed. The envelope is strict JSON `{payload,sig,alg}` and reuses the reviewed Clone Blocker Ed25519 public key under the distinct `threadsmod-app-update` purpose. Canonical scalar verification rejects Ed25519 malleability.

The signed payload owns `v`, `purpose`, `packageName`, `revision`, `publishedAt`, `modBuild`, `minimumModBuild`, `versionCode`, `versionName`, `notes`, `apkSize`, `apkSha256`, `signerSha256`, and two or three `downloadUrls`. `publishedAt` must parse and round-trip exactly as UTC `uuuu-MM-dd'T'HH:mm:ss.SSS'Z'`; alternate ISO spellings are rejected, while age alone does not expire valid policy. Revision and mod build never roll back. A higher policy revision may retain one mod build only when its binary identity is unchanged. Partial/wrong-type rollback floors fail closed. The parsed envelope must match the typed revision/mod-build floors exactly; if it does not, repair requires a candidate revision strictly greater than the strongest parsed or typed revision. Cached verified policy remains authoritative offline. Persistence uncertainty latches before policy commit, retains the strongest attempted verified policy in a process-local floor across thrown/false editor outcomes, rejects ordinary loads and older candidates, and clears the latch and floor only after a successful live signed recommit. During uncertainty, only `UpdateStore` may retain a previously successful load/commit that required this running mod build. It exposes only a boolean to the controller, which may show only noncancelable **Update unavailable** with **Retry**; the retained manifest cannot reach Update, unknown-sources, download, verification, current-binary, installer, write, or anti-rollback authority. Failed first-run and optional policies cannot create a lock.

An update is offered only when both its mod build and Android version code exceed the installed values. It is required only when the installed mod build is below `minimumModBuild`. Optional UI has Update and Later; Later synchronously persists exactly that signed revision. Back cancellation of an optional dialog runs the no-update continuation (the demo fallback through revision 1, the empty Runnable since revision 2) without persisting Later. Required UI from a successful persisted load has only Update, rejects back/outside cancellation, and returns on every foreground resume until a higher signed policy or successful install changes applicability. A metadata worker-start failure clears in-flight ownership, re-evaluates persisted policy, and otherwise uses only the boolean retained-required unavailable/Retry gate described above; it cannot manufacture a first-run lock or authorize an install from retained state. Android unknown-source and package-installer consent remain mandatory and cannot be simulated or bypassed.

APK transfer begins only after the explicit Update tap. Initial artifact URLs must be a canonical GitHub release or public CloudFront/regional-S3 object, with two independent provider classes in every manifest; a regional-S3 bucket must be one lowercase 3–63 character DNS label, never a dotted bucket. Initial URLs are capped at 1,024 characters; redirect Location/full URL at 4,096; redirect path/query at 2,048. Only 301, 302, 303, 307, and 308 redirect, at most three hops and never across provider classes. Each download attempt has a ten-minute monotonic deadline and the complete download/cache/hash/rename operation has a twenty-minute deadline. The isolated client refuses a process-wide CookieHandler, sends only a fixed updater User-Agent plus content Accept headers, disables caches and automatic redirects, and never sends Threads cookies, authorization, account IDs, or referrers. `tree55.com` is forbidden.

The completed file stays under `cache/shared/updates`, already covered by the 010-owned clone FileProvider. Updater-created storage is bounded to the fixed `threadsmod-update.apk` committed file and `threadsmod-update.apk.part` partial file; signed URL basenames remain policy validation and never become local paths. Before `ACTION_VIEW`, the updater proves exact byte count and SHA-256, clone package name, exact signed versionName/versionCode with a versionCode strictly newer than installed, exactly one signer, equality between installed/archive/metadata signer hashes, and the resolution-pinned signer. It uses only a one-shot read-grant URI. A completed download may launch only for the same current resumed Activity and still-showing dialog, and `UpdateStore.runIfCurrentBinary` reloads and revalidates the latest signed binary under the same monitor as policy installation immediately before the installer callback. `DownloadManager` is forbidden because its different UID would escape the app-scoped SOCKS5 VPN boundary.
