# 030 — Version-bound native block bridge

This patchlet is the only adapter between stable mod code and private, obfuscated Threads APIs. It renders two smali templates from `resolution.bridge.symbols`:

- `ThreadsBlockBridge` for a callback-free passive already-blocked preflight, an optional opaque resolved-model handoff, exact target-ID validation, cache lookup, session-cache get-or-create fallback, already-blocked detection and mutation submission;
- `MutationCallback` for started, success, failure, cancellation and ambiguous terminal callbacks.

Revision 7 makes both the template tree and the human-reviewed rendered reference tree exact-resolution inputs. The 444 mapping uses Threads' reviewed 13-argument mutation layout—context, model interface, session, callback, integer, seven strings, and operation integer—while the historical 415 mapping uses its reviewed 12-argument layout. The widened 444 range invoke copies high parameter registers into low temporaries before ordinary invokes and keeps those copies outside the narrow private-seam try regions. The signed-Dex inspector and its 275-case fixture matrix test the model-before-session layout, immutable target flow, all-zero tail, and exact native call; an unknown parameter layout fails closed.

## Why it is resolution-bound

Obfuscated names are not an API. Every symbol, field, method descriptor, callback method and the block operation meaning must be proven in the exact decoded APK whose SHA-256 appears in the resolution. The current evidence includes the native user-cache factory and get-or-create method, a same-APK numeric-UserId call site, the block route, method descriptor shapes and mutation callback interface.

Template rendering fails if:

- any required binding is missing;
- a placeholder remains after rendering;
- a proof does not match the decoded APK;
- a generated descriptor does not assemble;
- the bridge class already exists with different content;
- operation zero is not proven to mean block;
- any callback method is unaccounted for.

Already-blocked targets may complete without submitting a mutation. A real mutation is counted only after the native started callback, and completion is recorded only after native success. Failure, cancellation, ambiguous end and timeout do not become success.

## Resolved-model and cache-placeholder paths

Revision 3 added one SHA-bound fast path for inline rows. Stable Java may pass the displayed author model only as `java.lang.Object`; the rendered Smali bridge owns the private-model cast and accessor. Before using that model, the bridge reads its canonical numeric ID and requires it to equal the separately validated requested target ID. An invalid cast/template value fails as `resolved_model_invalid`; an absent, non-canonical, or mismatched ID fails as `model_id_mismatch`. Neither becomes authority to mutate another account.

Revision 4 removes the failing profile-info fetch prerequisite for automatic and hintless work. The bridge still checks the ordinary user cache first. On a miss it calls this exact APK's session-owned user-cache factory and its native `getOrPut(null, numericId)` seam, which the host itself uses for a numeric `UserId`. That seam returns a session-initialized native user model whose ID is independently checked by `blockModel` before the existing official block helper is invoked. A null placeholder fails as `placeholder_model_invalid`; a wrong ID fails as `model_id_mismatch`. Unexpected private-seam failures are separated into the reviewed session/cache/dispatch stages below. The obsolete `UserFetchCallback`, `users/%s/info/` dependency, and `lookup_failure` terminal are not rendered.

Revision 5 replaces the shared mutable stage register and broad catch ranges with narrow `Throwable` regions and callback-free preparation. The direct-ID entry isolates its session cast, ordinary-cache lookup, cache factory, and cache placeholder construction, then calls `blockModel` outside those ranges. The resolved-row entry separately isolates its session and opaque-model casts, then also calls `blockModel` outside. `prepareModel` has no callback or mutation: it isolates the model-ID accessor and already-blocked predicate and returns only `null`, the internal `already_blocked_success` sentinel, or a fixed reviewed failure stage. `blockModel` guards only that callback-free preparation call, interprets its result outside the range, constructs `MutationCallback` outside every range, and isolates only the native mutation invoke. This makes the signed-Dex result/literal-to-callback flow explicit and avoids JADX's prior uninitialized-stage rendering.

Revision 6 adds `passivePreflight(Object session, String targetId): String` solely for the passive automatic lane. It repeats the exact-SHA cache-first session/model resolution under its own four narrow private-seam regions, then calls the same callback-free `prepareModel`. It returns `null` only for an exact-ID model whose reviewed native predicate says not blocked, `already_blocked_success` only when that predicate says blocked, or one existing fixed failure stage. It performs no persistence, pacing reservation, scheduler transition, callback, report, or native mutation. The passive scheduler must call it while holding the same generation/admission exclusion boundary after final current membership but before `passive_running` persistence and the atomic attempt-plus-delay reservation. A pre-existing native Block therefore creates neither an attempt record nor a pacing deadline; the ordinary bridge repeats model-ID and blocked-state preparation before any mutation to close state drift after preflight.

The deterministic r6 bridge corpus retains the release-pinned total of 275 cases while replacing retired list-selection/pre-pace negatives with eleven focused preflight cases. They reject a missing preflight; movement after admission, running persistence, or reservation; an extra manual caller; callback or mutation authority in preflight; widened or shared try regions; fixed-stage drift; and a same-owner second-target mutation. The focused replay at `work/preflight-bridge-suite-275-i` passed all 275 cases on 2026-09-02. This is static signed-DEX-shape evidence only; the private symbol mapping and native callback meaning remain human-review requirements, and no live account mutation is claimed.

For an accepted host user type, the exact host mutation invokes its started callback synchronously. Its invalid-user-type guard can instead return before any native callback; the scheduler watchdog closes that path as review-required `callback_timeout` uncertainty with viewer/target quarantine, never as success or ordinary retryable failure. Neither `ThreadsBlockBridge` nor `MutationCallback` directly invokes `BridgeCallback`: every cast/cache/preparation/already-blocked/mutation-exception result plus native started, terminal failure, cancellation, ambiguous end, and success goes through patchlet 020's `BridgeCallbackDispatcher`. Its main-handler post moves the real mod callback beyond the private host stack and the scheduler's bridge-selection/argument-load/invocation-only catch. Posting refusal fails closed; the real callback is not wrapped in a catch. The signed-Dex bridge-flow gate must prove the preparation result flow, mutation callback construction position, exact automatic/manual/bridge caller provenance, exact reviewed owner provenance for every resolution-supplied raw private seam call with no extra mod-namespace callers, handler topology, exact bridge/native dispatcher and delivery caller provenance, checked handler post, zero direct callbacks outside `Delivery.run`, bounded automatic/manual caller catches after scheduler handoff, direct callback consumers with no immediate repost, and delivery-only real callbacks before release.

Internal counts or ordered decoys are insufficient. In signed primary DEX, `passivePreflight` starts at its reviewed session cast and keeps cache lookup, factory, placeholder, shared preparation, and every fixed result reachable from entry; `block` starts at the reviewed session cast and its cache lookup, factory, placeholder, and dispatch remain reachable from method entry; `blockResolved` starts at the model-presence branch and keeps both the null delegation and resolved dispatch reachable; `prepareModel` starts at the author-ID call and reaches the equality, already-blocked, and fixed outcome routes; and `blockModel` starts at the preparation call before any result, callback construction, or mutation route. A leading return or unreachable duplicate topology fails `bridge-entry-reachability-contract`.

The rendered bridge and mutation callback may emit only the reviewed fixed stages `session_model_exception`, `cache_lookup_exception`, `cache_factory_exception`, `cache_placeholder_exception`, `bridge_dispatch_exception`, `resolved_model_invalid`, `model_id_exception`, `model_id_mismatch`, `already_blocked_exception`, `placeholder_model_invalid`, `mutation_exception`, `mutation_failure`, `mutation_ended`, and `mutation_cancelled`. The split pre-mutation stages identify which exact same-APK seam stopped without accepting or exposing exception text. Scheduler-owned catch-all, timeout, persistence, validation, and handoff stages remain outside this adapter. Patchlet 020's closed `BlockDiagnostic` map owns all user-visible/status/log wording; the bridge never formats an identifier, URL, host exception, or server response into a failure string.

The scheduler's durable manual enqueue/running state and attempt record occur before a mutation bridge is called; manual work does not use passive pacing. Passive preflight is deliberately earlier and may only classify the exact target as ready, already blocked, or fixed-stage failure; it cannot reserve or mutate. The bridge does not persist either a row model or a cache-created placeholder, does not replace the requested target ID with model data, and does not submit a mutation outside the existing native helper and callback.

## AI boundary

For a future APK the deterministic resolver first emits candidate symbols and evidence. AI may select candidate IDs and explain evidence. It may not invent a descriptor, write smali, infer block versus unblock from an obfuscated name, or alter production templates. The private model cast, target-ID accessor/equality proof, cache-placeholder factory/get-or-create seam, null-to-direct-ID fallback, and every terminal result are exact-version roles rather than stable Java assumptions.

Any new mapping for the mutation method, operation mode or callback terminal semantics requires human review before the proposal becomes a `verified-current` resolution. Confidence alone is not evidence.

This bridge uses a private Meta endpoint and may break or trigger account/integrity controls even when all static gates pass. Static resolution is not runtime proof.
