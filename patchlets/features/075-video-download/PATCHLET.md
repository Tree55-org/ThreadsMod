# 075: video saving

This patchlet owns a native post-menu entry and the private Android save flow. It never adds another UFI row control or changes the combined Block/report modal. Its canonical Java is independent of obfuscated Threads classes; the captured media and progressive-video accessor belong only in the exact-SHA Smali adapter.

An explicit Save video tap opens a non-exported Activity. Choose location invokes Android's `ACTION_CREATE_DOCUMENT` picker for `video/mp4`. Only after a destination is selected does one worker fetch the captured URL inside the clone's UID. HTTPS URLs are restricted to the reviewed `cdninstagram.com` and `fbcdn.net` host families, including the roots and proper subdomains. Credentials, userinfo, nondefault ports, control characters, alternate hosts, and excessive URL lengths fail closed. Redirect destinations receive the same validation, with at most three hops. Cookie-handler presence fails closed; the feature never imports Threads headers, cookies, or session tokens.

The worker streams to private cache with a 256 MiB declared/received bound and a three-minute abort deadline. It validates the MP4 box structure before copying to the selected document. The Android destination is opened with a CancellationSignal before wrapping its file descriptor in AutoCloseOutputStream, and a pending provider open is registered for watchdog/lifecycle cancellation before output acquisition. Provider cancellation and stream closure occur off the main thread; a provider that ignores cancellation can still delay completion. Success is shown only after the destination stream closes. Failure or cancellation deletes the cache and tries to remove the incomplete document, without retrying automatically. The destination provider may be local storage or a provider explicitly selected by the user.

There are no preferences, database tables, storage permissions, exported components, background jobs, Block calls, report calls, analytics, or backend write endpoints. Activity replacement/process interruption never creates another download automatically. Unsupported media have no usable Save action. Carousel/adaptive-only coverage must be stated from the reviewed native accessor evidence.

The resolution stays `review-required` until human review of the native seam and exact signed candidate. Static fixtures, pristine replay, whole-series content idempotency, raw signed-DEX checks, archive/alignment/signature checks, and the no-permission Activity shell probe precede that review. A SignedReview APK remains under `work/`; only a separately authorized Release replay may transactionally publish under a fresh `dist/` path. Live feed selection and actual video delivery are separate runtime boundaries.
