# Update the mod for a future Threads APK

Patchlet 090 r57 retains r53's, r52's, and r50's rules that decoded Smali filenames are non-authoritative when the exact APK contains class descriptors that collide under the host filesystem's case rules. A collision proof may name only its exact reviewed candidate paths, must resolve exactly one target and one sibling by their exact `.class` descriptors, and may count its semantic needle only in the selected target. Fixture builders must preserve null as absence: a missing-candidate negative must prove the exact path does not exist before evaluation and require the core evaluator's exact missing-file rejection, never an empty-file or later class-declaration failure. Missing, duplicate, extra, mixed, or malformed mappings remain blocking; never repair drift by swapping a `.1` suffix or broadening the search tree. Revision 56 also retains r51's requirement that every targeted-JADX exact call count be derived from the selected exact-version template and pinned to that reviewed source version, plus the exact eleven-string `AutoBlockSync` wrapper baseline introduced to close r53 drift. The current reviewed register/update/unregister tuples are `2 / 1 / 3` for Threads 444 and `2 / 1 / 1` for historical Threads 415; a future version must receive its own human-reviewed tuple and count-drift negative rather than copying either value. Its three invalid-generation recovered expressions remain secondary readable evidence only: raw signed DEX, not local names or a rendered catch `0L`, must prove the underlying producer-to-consumer value flow.

Patchlet 085's in-app updater does not weaken this workflow: downloaded bytes remain only a candidate until signed metadata, package/version, size/hash, signer continuity, and the visible Android installer all succeed.

The update workflow reuses stable assets and patchlet contracts. It does not reuse the previous modified APK tree or assume obfuscated symbols survived. ## 1. Acquire and inventory the source

Place the complete delivered APK set in an input location outside `patchlets/assets`. Record every member name, role, size and SHA-256 plus the aggregate APK-only tree SHA-256 before trusting filenames. Inspect package, manifest version, SDK levels, ABIs, signer lineage, split names/types, `hasCode`, DEX count and archive integrity.

For a split delivery, run the bounded [`tasks/RESOLVE-SPLIT-SOURCE-UNIVERSALIZATION.md`](tasks/RESOLVE-SPLIT-SOURCE-UNIVERSALIZATION.md) workflow first. A reviewed resolution must name every required member and pin APKEditor/ARSCLib versions, JAR hash, ordered arguments, preservation counts, and the exact deterministic derived SHA-256. Missing or additional APKs, a partial set, tool drift, or a non-reproducible merge remains blocked. Do not decode/rebuild a resource split with Apktool or substitute a raw ZIP graft.

## 2. Decode into an isolated run

Snapshot the exact split members, run two independent pinned APKEditor merges, and require byte-identical unsigned outputs. Prove all root DEX, selected-ABI native-library, and selected-density payload bytes plus resource configurations before decoding the derived standalone APK with the pinned toolchain into a new path keyed by its digest. Preserve that pristine tree. All candidate extraction is read-only against it.

Never start from `work/mod-*`, a prior aligned APK, or a prior patched decode.

## 3. Look up an exact resolution

Use a resolution only if `resolution.source.splitSetSha256` equals the exact source-set tree digest, every `splitMembers` binding matches, and `resolution.source.sha256` equals the twice-derived standalone APK digest. Re-run every stored proof. A proof mismatch invalidates the run even if version name and descriptors appear unchanged.

If no exact reviewed resolution exists, enter resolve-only mode. Do not apply a previous version's rewrite files or bridge templates with old bindings.
